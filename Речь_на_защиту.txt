Команда 7. Речь по слайдам.

Сайт открывать через Открыть_сайт.bat. Презентация: кнопка «презентация». Стрелка вправо листает слайд. Тёмная кнопка на слайде открывает пример. Внизу экрана «к слайду N» возвращает на тот же слайд. На примере кнопки «назад», «дальше», «само» листают кадры.

Слайд 1. Подъячий Глеб.
Команда 7, КИПУ. Тема: сортировка в современных языках. Python, Java, C#, JavaScript и C++. Мы не писали сортировки заново. Мы смотрели, что вызывается, когда в языке пишут sort.

Слайд 2. Подъячий Глеб.
Одинаковое имя прячет разные алгоритмы. Где-то устойчивый Timsort, где-то быстрая сортировка, а пирамида стоит на подхвате. Мерили встроенные функции на одних и тех же массивах. До выбора два вопроса: нужна ли устойчивость и есть ли в данных уже готовый порядок. Дальше каждый говорит про свой язык, не меньше минуты.

Слайд 3. Подъячий Глеб.
Семь вызовов. Python, объекты Java и JavaScript хранят порядок равных. C# Array.Sort и C++ std::sort не хранят. Java для голых чисел устойчивость не обещает: две одинаковые пятёрки неразличимы. C++ std::stable_sort хранит, это уже другое слияние.

Слайд 4. Подъячий Глеб.
Две двойки равны по значению. Буква А стояла левее буквы Б. Устойчивая сортировка числа выстроит, а А и Б не поменяет. Неустойчивая может поставить Б левее.
Нажми «Две двойки».
На странице по очереди: «Как было», «Устойчивые», «Без гарантии». Скажи: проверка была на 400 парах, не на десятке. Короткий кусок introsort добивает вставками и случайно сохраняет порядок.
Нажми «к слайду 4».

Слайд 5. Подъячий Глеб.
Timsort не ломает готовое. Он ищет серии вверх или вниз, нисходящую разворачивает, короткую добирает вставками. Потом серии сливает. Равные забирает слева, поэтому порядок хранится. С Python 3.11 порядок слияния выбирает Powersort: не клеить крошку к гиганту, если рядом ровнее пара. Так устроены Python, объекты Java и V8.
Нажми «Серии Timsort».
Листай «дальше»: серия 3, 4, 5, потом 1, 2, потом разворот 9, 8, 7. Один кадр, одно действие.
Если останется время, «к слайду 5», затем «Короткие вставки»: равных вставки не перепрыгивают. Потом снова «к слайду 5».

Слайд 6. Подъячий Глеб.
Цифры Python. Случайный миллион: 277 миллисекунд. Уже упорядоченный: 5,86. Порядок равных сохранился. 277 рядом с объектами Java, 260, и далеко от Java для int, 48. Это цена языка и сравнения, не приговор Timsort.

Слайд 7. Керимов Андрей.
В Java две функции под одним именем. Для int это Dual-Pivot Quicksort: два опорных, три части, короткие хвосты добивают вставками. Готовые серии реализация замечает, поэтому упорядоченный миллион занял 0,11 миллисекунды против 48 на случайных. Для Integer это устойчивый Timsort, на том же случайном миллионе 260. У голых чисел нет «кто был левее». У объектов есть, и Java это хранит.
Нажми «Два опорных».
Покажи кадры: два опорных 3 и 7, 8 уезжает вправо, 1 уезжает влево, получаются три части.
Нажми «к слайду 7».

Слайд 8. Мамбетов Родион.
Array.Sort в C# это introsort. Обычно быстрая сортировка. Кусок короче 17 элементов уходит во вставки. Слишком глубокая рекурсия уходит в пирамиду, и худший случай остаётся n log n. Случайный миллион: 48 миллисекунд. Порядок равных на 400 элементах сломался. Если порядок важен, берут не Array.Sort, а LINQ OrderBy: при равенстве сравнивается исходный номер.
Нажми «Introsort».
Покажи проход вокруг опорного, потом короткий кусок, который добивают вставками, потом плохой вход, который отдают пирамиде.
Нажми «к слайду 8».

Слайд 9. Кулиш Артём.
С 2019 года JavaScript обязан сортировать устойчиво, но алгоритм стандарт не назначает. Node и Chrome, движок V8, используют Timsort. Замер в Node 24: 175 миллисекунд на случайном миллионе и 8,88 на упорядоченном. Порядок равных сохранился.
Нажми «Ловушка строк».
Нажми «sort() без сравнения». Массив 10, 2, 1 становится 1, 10, 2: строка «10» меньше строки «2». Потом «sort((a, b) => a - b)»: получается 1, 2, 10.
Нажми «к слайду 9».

Слайд 10. Черакаев Антон.
Собирали компилятором Microsoft Visual C++. std::sort это introsort: на месте, вставки до 32 элементов, при плохой глубине пирамида. Устойчивости нет. На случайном миллионе 55 миллисекунд. std::stable_sort это слияние, 52 миллисекунды, и порядок равных оно сохранило.
Нажми «std::sort».
Это тот же каркас, что у Родиона, только порог вставок 32, не 16. Один проход и предохранитель пирамидой.
Нажми «к слайду 10».
Нажми «stable_sort».
Два готовых куска. Каждый кадр сравнивает головы и забирает меньшую. Если головы равны, берётся левая, поэтому слияние устойчиво.
Нажми «к слайду 10».
Правило: нужны числа и скорость, вызываем std::sort. Нужен прежний порядок равных записей, вызываем stable_sort.

Слайд 11. Подъячий Глеб.
Как мерили. Один генератор, зерно 7. Пять рисунков: случайный, вверх, вниз, десять разных значений, почти упорядоченный. Размеры 10 тысяч, 100 тысяч и миллион. Все языки читали один файл. Первая попытка выбрасывалась, дальше медиана пяти. Чтение файла в время не входит. От 100 тысяч к миллиону время выросло примерно в 12-14 раз. Это n log n.

Слайд 12. Подъячий Глеб.
Случайный миллион. Java для int, C# и C++ стоят рядом, около 48-55 миллисекунд. JavaScript 175, объекты Java 260, Python 277. Разрыв это цена объектов и языка.

Слайд 13. Подъячий Глеб.
Уже упорядоченный миллион. Java int: 0,11 миллисекунды вместо 48. Python: 5,86 вместо 277. Готовый порядок адаптивные реализации используют.

Слайд 14. Подъячий Глеб.
C++ не быстрее как алгоритм. 48 и 277 миллисекунд это цена языка и объектов. Java int на убывании тоже почти мгновенный, 0,64: видит длинную серию вниз. Стандарт C++ не обязывает именно introsort, это выбор MSVC. Стандарт JavaScript не обязывает Timsort, он обязывает устойчивость. Timsort здесь потому, что движок V8.

Слайд 15. Подъячий Глеб.
Вывод. sort в разных языках не означает один алгоритм. Хранят порядок и любят готовые серии: Python, V8, объекты Java, std::stable_sort. Быстрые и почти на месте: std::sort, Array.Sort, Java int. Короткий кусок везде добирают вставками. Квадрат у introsort обрывает пирамида. Выбор зависит от двух вещей: порядок равных и готовые куски в данных. В JavaScript для чисел нужен компаратор (a, b) => a - b.
